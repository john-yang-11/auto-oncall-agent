# Auto On-Call Agent

An autonomous incident-response pipeline: when an alert fires, it identifies
the likely bad commit, retrieves the matching runbook, estimates impact,
posts a Slack brief, and drafts a postmortem once resolved.

Built as a learning project to go from "knows nothing about SRE/incident
response" to a working system, one honestly-scoped milestone at a time. The
project deliberately reframes "AI does root cause analysis" as "AI surfaces
ranked suspects with cited evidence for a human to confirm" throughout.

## How it works

1. **Alert ingestion** (`service/alert_webhook.py`) -- a FastAPI endpoint
   receives an alert (endpoint, first-seen time, message).
2. **Suspect-commit identification** (`service/commit_analyzer.py`) -- finds
   the most recent deploy before the alert, pulls its diff, and asks Claude
   to judge plausibility (hedged, cited -- never asserted as certain).
3. **Runbook retrieval** (`service/runbook_search.py`) -- embeds the alert
   and a small set of markdown runbooks, matches by cosine similarity (hand-
   rolled, no vector DB -- unnecessary at this scale).
4. **Impact estimation** (`service/impact.py`) -- plain arithmetic over
   metrics: error-rate multiple over baseline, traffic share affected.
5. **Slack brief + persistence** (`service/slack_notifier.py`,
   `service/incident_store.py`) -- posts a structured Block Kit card and
   saves the full incident record to `incidents.json`.
6. **Postmortem generation** (`service/postmortem.py`) -- on resolve, drafts
   a markdown postmortem from the stored facts only (no invented details).

A stretch variant (`service/github_commits.py`, `service/github_webhook.py`)
swaps the toy repo for a real GitHub repo via the REST API and a signature-
verified push webhook.

## Setup

```
pip install -r requirements.txt   # or install packages listed below
cp .env.example .env              # fill in ANTHROPIC_API_KEY at minimum
python seed_toy_repo.py           # generates toy_app/, deploys.json, ground_truth.json
python simulator/metrics_generator.py   # generates metrics.json
```

Dependencies: `fastapi`, `uvicorn`, `requests`, `pydantic`, `python-dotenv`,
`anthropic`, `sentence-transformers`, `numpy`.

`SLACK_WEBHOOK_URL` is optional -- without it, briefs print to the console
instead of posting to Slack, so the pipeline is fully runnable without a
Slack workspace.

## Running the demo

```
uvicorn service.alert_webhook:app --port 8000    # in one terminal
python simulator/fire_alert.py                   # in another
```

`fire_alert.py` detects the ongoing synthetic anomaly (an intentionally
seeded, subtle bug in `toy_app`: an expiry-clock unit mismatch that purges
links almost immediately, turning a normal 404 into an unhandled 500) and
posts a realistic alert. The webhook resolves the suspect commit, matches
a runbook, estimates impact, posts the brief, and saves the incident.

To draft a postmortem once "resolved":
```
python service/postmortem.py <incident_id>
```

## Why the toy app and metrics are gitignored

`toy_app/`, `deploys.json`, `ground_truth.json`, and `metrics.json` are all
generated by `seed_toy_repo.py` / `metrics_generator.py`, not hand-authored
-- committing them would just be committing build output. Running the two
generator scripts reproduces the same *structure* (a seeded bug, matching
metrics spike) with fresh commit SHAs and current-relative timestamps each
time.
